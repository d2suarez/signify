# Signify Learning

The LMS. A lesson is a list of **blocks** that is at once the plan, the live presentation and the student view. Planning, decisions and roadmap: `signify-learning/PLAN.md` in the Google Drive planning folder (not in this repo). Read it before adding features.

Started 2026-10-28. Deployed at https://learn.signify.one (open to one account via `LEARNING_ONLY`). Next.js 16 (App Router, React 19, TypeScript) behind a thin Express `server.js`; Postgres in production, PGlite (Postgres in WebAssembly) locally and in tests; socket.io for live lessons.

This is NOT the Next.js in your training data: params are Promises, etc. Read `node_modules/next/dist/docs/` before using an unfamiliar API.

## Run / test
- `export PATH=$HOME/.local/node/bin:$PATH`; install with `npm ci --no-workspaces`.
- `npm run build` then `npm run local` (port 3120, made-up teacher, refuses to start on Railway). Switch person with `/dev/as/teacher`, `/dev/as/admin` (school admin: grading periods), `/dev/as/student` or `/dev/as/guardian` (a parent whose one child is the dev student) (a cookie, so it switches every tab in that browser; an already-connected live socket keeps its ticket). Launch configs `signify-learning` (3120) and `signify-learning-3121` (own database in `data/pglite-3121`, for when another session holds 3120) in the Drive folder's `.claude/launch.json`. Local data lives in `data/pglite*` (gitignored); delete it to start fresh. Note `npm run build` rewrites `.next` under any server already running from this folder. The dev cookie is per host, so it switches localhost:3120 and :3121 together.
- `npm test` (tsx + node:test): blocks, courses, lessons (versions, conflicts, school isolation), units, assignments, submissions, grades, grade maths, FACTS order and file on in-memory PGlite, plus real socket.io round trips for live lessons (polls, picker, noise), reading supports, read-aloud chunks, Boards links, writing-process recording, announcements, calendar dates and the Sabbath rule, planner school-day maths, pacing modes, Common Cartridge import (zip bomb / path traversal / XXE refusals, HTML to blocks, the plan, one-transaction writes, rollback on failure), drop lowest, rubrics, parent view and This week, LTI 1.3 launches against a fake platform (bad signature, tampered claims, unknown kid, alg none, replayed state and nonce, wrong audience, expired, wrong version/type/deployment/target, wrong person, other school, LTI role ignored), Deep Linking (signed answer checked against our JWKS, line items, one-item platforms, cancel, only the linked course's items, students refused, answer taken once) and grade passback against a fake platform (token endpoint checks our signed client assertion, Names and Roles, line item lookup, scores; a save never calls the platform; late/missing/exempt/unreleased rules; backoff to failed, Retry; stale sends can't overwrite newer), standards-based grading (summaries, conversion, alignment, and proof that points courses give byte-identical grades and FACTS files), quizzes (every question type's scoring, partial credit, shuffles, no key to students, autosave conflicts, server time limit and late saves, attempts + accommodations, teacher scores, regrade with history, standards levels, item analysis, other school refused), the off-site database backup (stub bucket: encrypted, no private keys, restored table for table), QTI 1.2 quiz import (each type, `<not>` ignored, DOCTYPE/bank/untakeable refused, imported quiz is a draft quiz, discussion as writing assignment). 151 tests.

## Shape
- `server.js`: sign-in via `signify-auth.js` (verbatim fleet copy, never fork), dev people, passes the person to Next on `x-signify-user` and the token valid for this request on `x-signify-token` (both deleted from incoming requests first). Merges later Set-Cookie writes (same reason as the Help Desk). Attaches `live.js`.
- `live.js`: live lessons over socket.io at path `/live`. One session per course, in memory on `globalThis.__learningLive` (Next reads it in the same process to know which lesson is live). The teacher's screen is the truth; state is sent absolute and in full on every connect. Students see counts only when revealed, never names or who answered what.
- **Pacing** (`live:pace`, teacher only): `teacher` ("Follow me": every screen on the teacher's block), `review` ("Look back": students may go back, never past the teacher; a teacher move brings them along) or `self` ("Own pace": anywhere in the lesson). Outside `teacher`, the student's screen sends `live:at {index}` (clamped to the teacher's block in review) and the teacher sees each student's slide and a count on each strip slide (`positions`). `live:start` sends the lesson's `blockIds`, so `canSee` takes poll answers for any block the student may see. Timers, revealed results, picks and the noise level stay on the teacher's block only.
- **Projector view** `/lessons/[id]/project` (teachers; "Projector view" on the presenter opens it in a new tab for the classroom screen; `Projector.tsx`): the teacher's current slide, large, with a full-screen button. It only listens (never emits), shows poll results only once revealed, and shows a picked name (as Teacher's Desk does on the board) but never who answered what.
- **Live tickets** (`src/lib/live-ticket.ts`): Next decides who may teach or follow a course and signs an HMAC ticket (12 h; secret made at boot in `LEARNING_LIVE_SECRET`). `live.js` checks the signature AND that the ticket's `sub` matches the Signify session on the socket. A teacher ticket names the one lesson it may present.
- **Off-site database backup** (`dbbackup.js`, `offsite.js` = byte-identical fleet copy, `restore-db.js`; same shape as Signify ID's). `server.js` starts it when `DATABASE_URL` is set: once a day (checked hourly, first a minute after boot) every table as Postgres text in one REPEATABLE READ snapshot, gzipped JSON, AES-256-GCM with `BACKUP_ENCRYPTION_KEY`, to `R2_BUCKET` under `learning/`, pruned at 28 days; the log line lists rows per table. Left out: `lti_keys` (private keys; `toolKey` makes new ones on first use), `lti_states`/`lti_nonces`/`lti_launches`, `schema_migrations`. Off unless `R2_ENDPOINT` (US-jurisdiction buckets need `https://<acct>.us.r2.cloudflarestorage.com`), `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` and a valid key are set; with no key it sends nothing. Restore into a NEW empty database (migrated first; refuses one with courses): `node restore-db.js <file> [--pglite <dir>]` or `--latest` (downloads the newest from the bucket; needs the R2 vars); prints backup vs restored rows per table. Key: `read -rs BACKUP_ENCRYPTION_KEY && export BACKUP_ENCRYPTION_KEY`.
- `src/lib/db.ts`: `getDb()` singleton on globalThis; `tx()` runs on ONE connection (pool BEGIN/COMMIT as separate queries is no transaction). Migrations in `migrations/NNN_*.sql`, applied on first use.
- `src/lib/roster.ts`: classes and members from Signify ID `/api/v1/classes` with the person's own token; cached a minute; a failure is never cached and never shown as "no classes".
- `src/lib/courses.ts`: one course per ID class. Teachers' classes become courses on sight; students only see courses a teacher has opened. Role is re-derived from live ID classes every request.
- `src/lib/lessons.ts`: every save names `baseVersion`; a stale save is refused (409), never written over. Each change first copies the previous state into `lesson_versions` (newest 50 kept). Restore is a new save, so it can be undone.
- `src/lib/blocks.ts`: block types `text`, `poll`, `timer`, the Desk tools `picker` (name picker) and `noise` (noise meter), `board` (Signify Board) and `link` (a web page opened in its own tab, never framed; only http(s) is ever opened, via `webLink`); `normalizeBlocks` is the only way in (drops unknown types, caps sizes, fixes ids). `forStudent` strips poll answer keys. `blockSpeech` is what read-aloud says.
- **Desk tools as blocks** (rebuilt here from `apps/desk` widgets, self-contained until `packages/tools` has a build step; pure maths in `src/lib/picker.ts`, `src/lib/noise.ts`). Picker: the teacher's browser picks (from students connected, or the class from Signify ID: the present page asks ID only if a picker wants it; "everyone once before anyone twice" by default) and sends `live:pick {blockId, studentId}`; `live.js` keeps who's had a turn per block in the session, tells the class only that a name was picked (`pick: {blockId, at}`) and sends `live:picked` to that student's sockets alone. Noise: the teacher's microphone (`useNoiseMeter`: analyser only, nothing recorded, off until pressed, off on leaving the block) sends `live:noise {level}` (0-100, ≤4/s, server drops faster); students see the bar. `Permissions-Policy` allows `microphone=(self)` for this.
- **Board block** (`src/lib/boards.ts`): only Signify Boards origins are kept (also the CSP `frame-src` list). A link to a board "shared to the web" (`/embed/<token>`, public read-only live view that Boards lets others frame) shows inside the lesson; any other Boards link is an "Open in Signify Boards" button (new tab, normal sign-in), because Boards refuses framing elsewhere. For a local Boards build with `NEXT_PUBLIC_BOARDS_DEV_ORIGIN=http://localhost:3231` (launch config `whiteboard-open`); never set it on Railway.
- **Reading supports (UDL)**: `src/lib/prefs.ts` (shape, `normalizePrefs`, `prefsAttrs`; pure) and `prefs-store.ts` (table `student_prefs`, migration 003, per Signify id + tenant). Anyone signed in sets their own via the "Reading supports" dialog in the top bar (`Supports.tsx`, `PUT /api/prefs`). The layout puts the choices on `<html>` as `data-font|size|spacing|contrast|read-aloud|rate`, so `globals.css` applies them on first paint (font = OpenDyslexic, self-hosted from Boards' files; size = `zoom` on `main`; wide spacing ≥ WCAG 1.4.12; high contrast in light and dark). Read-aloud: `ReadAloud.tsx` + `speech.ts` (browser speech synthesis, one voice per page, sentences ≤220 chars because Chrome stops long utterances; stops when its text changes) on the live block, assignment instructions and the student's own writing.
- `src/lib/i18n.ts`: every UI string, English + Spanish (falls back to English).
- `src/lib/units.ts`: a course's units, in order. A unit only groups: deleting one sends its lessons and assignments to "no unit". Which unit a lesson is in is filing, not content (no new lesson version).
- `src/lib/assignments.ts`: assignments (`online` = written and handed in here, `offline` = paper/in class, graded only) and submissions. Assignments save like lessons (baseVersion, 409 on stale, previous state kept in `assignment_versions`, newest 50; no restore screen yet). Archive, never delete. Students see an assignment only when `published`, and their grade only when `grades_released`. A submission is one row per student, autosaved with its own version (0 = never saved), handed in by `submitted_at`; taking it back is refused once graded. Due = `due_on` (the teacher's calendar day: decides the quarter) + `due_at` (the exact moment: decides late); the browser sends both.
- `src/lib/writing.ts`: **writing-process evidence** (migration 004, `writing_events`, keyed by submission). The writing box sends paste events (when, how many characters, the text up to 5,000) with its next autosave; `saveDraft` records them and a snapshot of the whole text (at most one per 15 s, 400 per submission) in the same transaction; hand-in always snapshots. Teachers see it on the grading screen under "How this was written" (`WritingReplay.tsx`, `GET /api/assignments/[id]/writing?student=`, teachers only): plain facts, a replay slider, every paste. The student is told under the box. Evidence, never a verdict: no score, no AI likelihood; keep it that way.
- `src/lib/announcements.ts` (migration 005): teachers post on the course page (server action `announce`, title optional, body ≤5,000), students see the newest 20 on theirs; "Take down" archives.
- **Class calendar** `/courses/[id]/calendar` (`CourseCalendar.tsx`, pure date maths and `onSabbath` in `src/lib/calendar.ts`): month grid plus a plain list for phones and screen readers. Teachers see planned lessons and every due date (drafts marked) with a ⚠ Sabbath chip on work due Friday from 6 pm or Saturday (browser's local time); students see published assignments only (a lesson stays the teacher's plan until presented).
- **Week planner** `/planner?week=YYYY-MM-DD` (teachers; button on the home page; `WeekPlanner.tsx`, pure school-day maths in `src/lib/planner.ts`): every course taught, Monday to Friday, lessons planned and work due. Move a lesson by drag or its "Move to" list (this week, next Monday, Not scheduled); "Push back" from a day (a lost day: every lesson from then on moves one school day later); "Plan a unit" (the unit's lessons one school day apart from a chosen day); "+ lesson" quick-adds a lesson on that day. Every move is a normal version-checked `PUT /api/lessons/[id]`; a 409 stops the batch and says so. Nothing is ever placed on Saturday or Sunday. "Today" is the school's day (`SCHOOL_TZ`, America/New_York for now).
- **Common Cartridge import** `/courses/[id]/import` (teachers; linked from the course plan and Grading settings; `ImportCourse.tsx`, `POST /api/courses/[id]/import?step=preview|import`, the body is the file, ≤150 MB, read with a running cap). Preview writes nothing; import sends the file again and `cc-import.ts` writes everything in ONE `tx()`. All drafts: assignments unpublished, lessons unscheduled; new units after existing ones; lessons/assignments start at version 1 like any new one. `course_imports` (migration 006) records each import with the file's sha256 (preview warns on the same file twice); `import_sources` keeps every quiz's QTI XML and discussion's text (so later versions can bring in more without a re-upload). Pieces, all pure apart from the db writer: `zip.ts` (own reader: entry count, per-entry and total inflated caps enforced while inflating, declared-size cap, `..`/absolute/drive names refuse the whole file, no encryption, no ZIP64, never touches disk), `xml.ts` (own parser: any DOCTYPE/ENTITY refused, so no XXE or entity expansion; prefixes dropped), `html-text.ts` (page HTML to plain text blocks, split at h1–h3; this IS the sanitizer, since text blocks hold no HTML; http(s) links written after their words, iframes become link blocks, images/files become "[Image: alt]" and are listed as not imported), `cartridge.ts` (manifest to plan: top-level folders = units, sub-folders flattened; webcontent pages = lessons, weblinks = a lesson with a link block, CC 1.3 `assignment_xmlv1p0` / Canvas `assignment_settings.xml` / look-alikes = assignments with points and due date (no zone = school's wall clock); QTI 1.2 assessments = quizzes via `qti12.ts` (own reader on the same safe `xml.ts`; type from CC `cc_profile` / Canvas `question_type`, else the response's shape: multiple choice, true/false (from the choices' words), multiple response (never what's under `<not>`), fill-in-blank → short (accepted answers, `case`), numerical (exact or a vargte/varlte range → value ± half), matching (one response_lid per left item), essay; `points_possible` else 1; `cc_maxattempts`, `qmd_timelimit`; HTML via html-text; other types listed as skipped questions; a quiz with no takeable question, a question bank, or unsafe XML is listed as not imported), discussions (`imsdt_*`) = online-writing assignments holding the prompt (`fromDiscussion`; no discussion feature yet, and the preview and result say so); LTI links, files, unknown types skipped and listed). Real Schoology exports haven't been tried yet: their exact resource types and QTI flavour are a guess from the spec and Canvas.
- `src/lib/grades.ts`: grades (score and/or flag `missing` | `late` | `exempt`, plus comment), every change appended to `grade_history` first; categories and the course's points-vs-weighted switch; the school's grading periods (admins only). `setGrade` takes the class's live Signify ID students and refuses anyone else; `/api/grades` refuses to write when ID can't be asked.
- **Drop lowest** (migration 007, `grade_categories.drop_lowest` 0–10, set per category in Grading settings): `computeGrade` leaves out each category's n lowest counted grades by percent (missing zero first; tie = the one worth more points; never the last one; 0-point extra credit never), in both points and weighted courses, and returns them as `dropped`. The grid strikes dropped cells through (word in label/tooltip, key in the legend); a student sees "· dropped" on that chip.
- **Rubrics** (`src/lib/rubric.ts`, pure; `assignments.rubric` jsonb, `grades.rubric` + `grade_history.rubric` = chosen level per criterion): criteria ≤20 × levels ≤6 with points; `normalizeRubric` is the only way in, `cleanSelection` keeps only real level ids. With a rubric the assignment's points = `rubricMax` (set on save, the points field is disabled). Grading screen: level toggle buttons (`RubricView` with `onPick`) fill in the score, which the teacher may still change; the grid sends no rubric, so typing a score keeps the chosen levels. Students see the rubric ("How this will be graded"), and their levels once grades are released. Rubric changes are in assignment versions.
- **Parents and This week** (`src/lib/family.ts`, `components/Work.tsx`): `roster.childrenFor` asks Signify ID `GET /api/v1/my-children` with the person's own token (only links the school verified on ID's Parents page; cached a minute; failure is reported, never "no children"; never stored). Home shows "Your children" for a guardian (or anyone ID gives children); `/family/[childId]` (child must be in ID's answer, else 404) shows each course from the child's ID classes that a teacher has opened (`studentCourses` never creates one), published work with due date and status (`workStatus`), scores only where grades are released, and the same released-only course grade the student sees. `/week` ("This week", students and parents): needs attention, due Mon–Sun, grades released in the last 7 days (`grades.graded_at`), next week, announcements of the last 7 days; `weekSummary` is pure. In-app only, no email (Railway Hobby blocks SMTP). In production parents also need to be on `LEARNING_ONLY` while that is set.
- **LTI 1.3 tool mode** (`src/lib/lti.ts`, migration 008; Schoology launches Learning, Schoology stays the record). School admins register a platform at `/school/lti` (issuer, client id, deployment ids (empty = any), auth/token/JWKS URLs, frame origins; Schoology's usual endpoints prefilled) and copy our URLs from it. `/lti/login` (GET or POST) stores state + nonce (`lti_states`, 10 min) and sets `sl_lti_state` (`SameSite=None; Secure`, Path=/lti, last 5 states) then redirects to the platform. `/lti/launch` (form_post) runs `checkLaunch`: RS256 only, signature against the platform's JWKS (cached 10 min, refetched once for an unknown kid) BEFORE any other claim is believed; aud (azp when several), exp/iat (60 s skew), state spent on first use, nonce must equal the state's and is recorded in `lti_nonces`, version 1.3.0, `LtiResourceLinkRequest` only, deployment, target_link_uri on our origin, context required. A cookie that's sent must name the state; none is allowed (Safari blocks third-party cookies in frames). A good launch is kept in `lti_launches` (30 min, email + context only, no person) and the framed page offers "Open Signify Learning" in a new tab (straight on when not framed), because Signify's Lax session cookie never reaches a frame. `/launch/[id]` needs the person's own Signify sign-in: same school and same email as the launch, else refused (no email from the platform = refused, so Schoology must send email). The LTI context opens the course a teacher linked once (`lti_contexts`, teacher picks from courses they teach per live ID classes); the course's role is always Signify ID's, the LTI role is ignored. Framing: `next.config.ts` leaves `/lti/*` out of the static headers and `src/app/lti/respond.ts` sets each response's CSP with `frame-ancestors` = that platform's registered origins only (`'none'` when unknown). Our keys: one RSA key per school in `lti_keys`, made at registration, public half at `/.well-known/jwks.json` (rewrite to `/lti/jwks`); used later by Deep Linking and grade passback. Origin for redirect_uri: `LEARNING_ORIGIN`, else `https://$CANONICAL_HOST`, else the request host.
- **LTI Deep Linking** (`src/lib/lti-dl.ts`, migration 009): an `LtiDeepLinkingRequest` launch (needs `deep_link_return_url` https and `ltiResourceLink` in `accept_types`) shows, in the frame, "Open Signify Learning" and polls `GET /lti/deep/[launchId]` every 2 s. In the teacher's own tab `/launch/[id]` (course linked first if needed; teachers only, per ID) lists the course's assignments and lessons (checkbox, or radio when `accept_multiple` is false); "Add nothing" is an answer too. `placeItems` signs an `LtiDeepLinkingResponse` with the school's tool key (iss = client id, aud = issuer, echoes `data`): each item is `ltiResourceLink` with `url` `/lti/launch?item=assignment:<uuid>` and `custom.signify_item`; assignments add `lineItem` {scoreMaximum = points, resourceId = `assignment:<uuid>`, tag `signify-learning`}. Placed items go to `lti_items`. The answer is kept on the launch and handed out ONCE (`takeResponse`) to the frame, which form-posts `JWT` to the return URL (the frame page's CSP allows `connect-src 'self'` and `form-action` to that origin only). Not framed: the window goes to `/launch/[id]?w=1` and after placing to `/lti/deep/[id]/post`, which posts itself. Later launches of a placed link carry the item (custom claim, else the target's `?item=`): it opens `/assignments/<id>` (teacher and student), a lesson opens the editor for teachers and the course for students, and only if the item is in the linked course. Every launch keeps the course's AGS/NRPS addresses (`lti_context_services`), a placed assignment's first launch its `lineitem` URL, and a matched person's platform `sub` (`lti_users`, ids only).
- **Grade passback (AGS)** (`src/lib/lti-ags.ts`, `lti-passback.ts`, `/api/lti/scores`): after a grade save (`/api/grades`) or an assignment save while grades are released (release, points), `passBack` queues rows in `lti_scores` for each placement (one per platform course × student; the latest wish wins, `rev` bumped) and nudges `kickScores`; the save never waits on Schoology and a queue error is only logged. What goes = the gradebook rule (`scoreToSend`): a score as given (late is a mark only), missing without a score = 0, exempt and ungraded send nothing (exempt gets a visible "nothing sent" row), and nothing before `grades_released` ("goes when released"). Clearing a sent grade does not clear Schoology. The sender claims due rows (`FOR UPDATE SKIP LOCKED`, pushed 5 min), gets a token by client credentials with a JWT signed by our key (aud = token URL; cached till a minute before expiry), finds the platform user (`lti_users`, else NRPS by the email Signify ID gives teachers; the email is cleared once found) and the line item (`lti_items.lineitem_url`, else `GET lineitems?resource_id=`), and posts `application/vnd.ims.lis.v1.score+json` to `<lineitem>/scores` (FullyGraded, Completed, comment). Failures retry after 1, 5, 30, 120, 480 min, then `failed` until a teacher presses Retry; reasons in words (`ltiErr_*`). Every minute while the process runs, plus 30 s after boot in production (`src/instrumentation.ts`). Status shows on the grading screen (per student, after each save) and on the assignment page ("In Schoology", the class, Retry everything not sent), only when the assignment is placed.

- Deep Linking URL (content selection) `https://learn.signify.one/lti/launch`, placements: course materials / assignment selection.
- Services (scopes): `https://purl.imsglobal.org/spec/lti-ags/scope/lineitem`, `.../lti-ags/scope/lineitem.readonly`, `.../lti-ags/scope/score`, `.../lti-ags/scope/result.readonly` (optional), `https://purl.imsglobal.org/spec/lti-nrps/scope/contextmembership.readonly`.
- Privacy: send name AND email (launches without email are refused; NRPS emails match students for grade passback).
- Then a Learning school admin registers Schoology at `/school/lti` with the client id, deployment id, Schoology's token URL and the school's Schoology address as a frame origin.
- **Standards-based grading** (migration 010; per course, Grading settings → "Standards-based"). `courses.grading` = `points` (default) | `standards`; `courses.standards_settings` jsonb = scale labels (2–6 levels, top first, "" = the usual word), summary method (`recent` by due date / `mean` / `highest`) and the FACTS conversion table (average level ≥ min → percent; letter from that percent on the usual scale). Default table 3.5+ → 95 A, 3.0 → 85 B, 2.5 → 75 C, 2.0 → 65 D, else 55 F (an open question for Desmond in PLAN.md). `src/lib/standards.ts` (table `standards`: code, description, nullable `external_id` for CASE later; archived, never deleted) and pure `standards-math.ts`. Alignment: `assignments.standards` (ids) and a rubric row's `standardId`, both checked against the course's live standards on save and kept in assignment versions. Levels: `grades.levels` {standardId: level} (+ `grade_history.levels`), set on the grading screen (an aligned rubric row fills its standard's level in proportion), written by `setGrade` ONLY in a standards course and only for standards the assignment measures. Exempt = left out; missing = no evidence (listed in the checks). `buildGradebook` branches once: points courses never read any of this (tests prove the FACTS file is byte-identical), standards courses get `gb.standards` + `row.standards` and a `grade.percent` that is the converted percent, so the FACTS list/file, the student's badge and the parent view follow. Gradebook page shows `StandardsGradebook` (students × standards, read-only; the conversion table is shown in "Before you post"). Students and parents see each standard's level (released work only) under the course grade, and on the assignment.
- **Quizzes** (migration 011; `src/lib/quiz.ts` pure, `quiz-store.ts` db, `quiz-sync.ts`). A quiz is an assignment with `kind = 'quiz'`, so units, gradebook, calendar, This week, parent view, LTI placement/passback and standards alignment all apply unchanged. Questions + settings in `assignments.quiz` (jsonb), saved and versioned with the assignment (snapshot includes it); points = the questions' total. The model is QTI 3.0-shaped (table in `quiz.ts`'s header: kind → interaction, cardinality/baseType, `correct` = correctResponse, match pairs "source target" like a directedPair; `responseDeclaration` shows the mapping), so QTI import/export later needs no migration. Kinds: single, multiple (partial optional), truefalse, short (accepted answers, case-insensitive unless set; no key = teacher scores it), numeric (value ± tolerance, decimal comma ok), match, order (partial optional), essay (teacher-scored; writing box with paste capture + snapshots). `normalizeQuiz` is the only way in. Settings: attempts (0 = unlimited), keep highest/latest, time limit (min), shuffle questions/choices, results on hand-in or on release, show right answers. Attempts in `quiz_attempts` (one open per student by a partial unique index; layout = that student's shuffle, fixed at start; ordering questions never start solved). Autosave = whole answer set, version-checked; `deadline_at` fixed at start (limit × the student's time factor); saves after it + 30 s grace are refused and the attempt is handed in with what was saved, timed at the deadline (`closeExpired` also runs on every student/teacher page and API read). Hand-in scores it (`scoreAttempt`: a teacher's per-question score is kept, auto ones recomputed) and upserts a `submissions` row (status, late marks, This week). The grade: the counting attempt's score goes through `setGrade` (history, release, passback) once nothing waits for a teacher, keeping the grade's comment/flag (missing cleared); quiz-made writes are `changed_by = 'quiz'`; standards courses get levels in proportion per question standard (and the quiz's own standards over the whole quiz). Key changes (`scoringKey` differs) regrade every handed-in attempt on save and rewrite grades (PUT /api/assignments/[id] answers `regraded`). Teacher: editor in `QuizEditor` (inside AssignmentEditor), grading desk shows `QuizReview` (every answer + key, per-question score boxes, essays' writing replay via `/quiz/writing`), `/assignments/[id]/results` (percent correct per question = full marks share over counting attempts, choice picks, score by question, accommodations). ## Rules
- Every table has `tenant_id`, from the signed-in person's claims, never from a request body; every query filters on it.
- People are never stored here: Signify ID is the authority, asked live.
- New block types: add to `blocks.ts` (type, `newBlock`, `normalizeBlocks`, `forStudent` if it holds anything secret), the editor's `BlockFields`, and `Stage` in `Presenter.tsx`; add tests.
- Design: Signify tokens in `src/app/globals.css` (Bricolage Grotesque + IBM Plex, self-hosted; four block colours each with one shape). Block kinds: content = teal arch, poll/question = yellow triangle, timer = red circle, class tools (picker, noise) = blue square, board = teal arch. Lists: lesson = teal arch, assignment = yellow triangle, unit = blue square. Grade states always carry a word (Missing, Late, Exempt), never colour alone.
- A grade is only ever written for someone Signify ID says is a student in that class now. A student's own view counts only released grades.
- Live: students never receive another student's name or answer (picker included). The noise meter sends a loudness number only; never add recording.
- Every new string in `i18n.ts` gets Spanish too (supports test checks the new ones). New UI meets WCAG 2.1 AA: 44px targets, labels, colour never alone, works with every reading support on (try high contrast + Larger + dyslexia font).
